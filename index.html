Why An On-Chain Captcha Contract Fails Against Bots (And The Working Solution)

The Proposal: A 3-step contract where the browser triggers Call 1, solves a captcha, and triggers Call 2 within a 10-second window to release 10 DRB.

EVM Execution Reality: Smart contracts are public and deterministic. A bot monitoring the mempool or the public blockchain can call both Contract 1 and Contract 2 within the exact same block (or even via a single atomic smart contract transaction) in under 20 milliseconds. Furthermore, on-chain code cannot independently verify whether a web user solved an image captcha in their browser without an off-chain cryptographic signature.

The Real Solution (Option A — Fixed Caller Bounty): Instead of fighting bots with brittle on-chain timers, offer a fixed callerBounty (1 DRB) inside fillOil(). MEV searchers and keepers will happily pay Base gas 24/7 to pump the tank the instant the 10-second global cooldown resets, completely removing the need for you to run servers or pay gas.

The Real Solution (Option B — EIP-712 Signed Turnstile): If you strictly require human verification before a relayer submits gas, the user solves an off-chain Cloudflare Turnstile in the browser. A lightweight serverless backend verifies the token and signs an EIP-712 permit: (userAddress, nonce, deadline). The relayer submits the transaction only when the signature is valid.
